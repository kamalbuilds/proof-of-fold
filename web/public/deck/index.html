The Story of Proof of Fold

FoldingCash pays folders by pushing one payment per person. The sponsor API lists 56 rows for the pinned window and every one is a legacy 1... address, so there is no token-aware address to push to. We flipped the direction. The operator publishes one Merkle root per epoch, and each folder signs a claim with the key behind the address they already hold. The signature is the link, so no address-linking database exists to trust.

Benefits of Proof of Fold

  1. One root per epoch replaces one payment per folder
  2. Claim with the key behind your existing 1... address, into any token-aware wallet
  3. Payout leaves built from the live api.folding.cash GetDistro response, SHA-256 pinned on chain beside the root
  4. Anyone re-fetches the URL, rebuilds the tree and compares, in the page
  5. 2-of-3 operator proposals and a guardian veto inside the audit window
  6. 51 of 51 tests pass and 19 of 19 mutations turn the tests red

The Vision for Proof of Fold

Any sponsor that owes many people tokens publishes one root instead of one payment per person.

  1. Abstraction increases: a payout run becomes a single Merkle root
  2. Next priority -> the production profile of 144 block audit and 4032 block push windows
  3. Target: every FoldingCash epoch settled by one root
